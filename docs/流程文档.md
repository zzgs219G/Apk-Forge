# 流程文档

注入流水线的完整数据流与每一步的实现细节。

---

## 总览

```
Input: sourceApk, targetClass?, targetMethod, targetSignature, callsText, payloadDex?
  │
  ├─[1] 读 AndroidManifest.xml ──▶ AxmlManifest.parseBytes ──▶ packageName, launchers
  │
  ├─[2] 定注入点 ──▶ 用户指定 ?: launcher.first()
  │
  ├─[3] SmaliCallParser.parseAll(callsText) ──▶ List<Call> + errors
  │
  ├─[4] 遍历 classes*.dex ──▶ DexCallInjector.containsClass ──▶ hitDex
  │
  ├─[5] DexCallInjector.inject(hitDexBytes, spec) ──▶ newDexBytes
  │
  ├─[6] 校验 payloadDex 魔数 ──▶ payloadBytes?
  │
  └─[7] ApkRepackager.repack ──▶ 中间产物
       │
       └─[8] OutputStore.saveApk ──▶ Download/ApkForge/xxx_injected.apk
```

UI 通过 `onStep` 回调拿到每一步，驱动 `Phase` 枚举与动画。

## Step 1 — 解析 AndroidManifest

`ApkRepackager.readEntry(apk, "AndroidManifest.xml")` 取出原始字节，交给 `AxmlManifest.parseBytes`。

**全程只读字节，不产生文本 Manifest。**

AXML 结构：

```
RES_XML_TYPE (0x0003) 文件头
 ├─ RES_STRING_POOL (0x0001)    字符串池
 ├─ RES_XML_RESOURCE_MAP (0x0180)
 ├─ RES_XML_START_ELEMENT (0x0102)  ← 靠它拿元素/属性
 └─ RES_XML_END_ELEMENT (0x0103)
```

每个 chunk 头统一 `type(u16) headerSize(u16) size(u32)`。

### START_ELEMENT 的布局

```
偏移  字段
 8    lineNumber(4) comment(4)
16    ns(4) name(4)
24    attributeStart(u16) attributeSize(u16) attributeCount(u16)
      idIndex(u16) classIndex(u16) styleIndex(u16)
36    属性数组，每项 attributeSize（默认 20）字节：
        ns(4) name(4) rawValue(4) typedValue{ size(2) res0(1) dataType(1) data(4) }
```

属性取值优先级：`rawValue` 索引 > `dataType == TYPE_STRING` 的 data。

**为什么优先 rawValue**：对字符串型属性它总是给原始文本，比 data 索引更稳（某些 aapt2 版本会输出指向同一字符串池但索引不同的形态）。

### LAUNCHER 判定

维护一个元素深度栈，只关心：

- `manifest` → 取 `package`
- `activity` / `activity-alias` → 记下 `name`，开始收集
- `action` → `android.intent.action.MAIN`
- `category` → `android.intent.category.LAUNCHER`

`END_ELEMENT` 时若两者都命中，把类名归一化后加入结果。

**类名归一化**（`normalizeClassName`）：

| 输入 | package | 输出 |
|---|---|---|
| `.MainActivity` | `com.foo` | `com.foo.MainActivity` |
| `MainActivity` | `com.foo` | `com.foo.MainActivity` |
| `com.foo.MainActivity` | `com.foo` | `com.foo.MainActivity` |

## Step 2 — 定注入点

```kotlin
val resolved = input.targetClass?.trim()?.takeIf { it.isNotEmpty() }
    ?: manifest.primaryLauncher
    ?: return Result(false, "没填类名，且 Manifest 里找不到 LAUNCHER")
```

用户填了就优先用用户的——自动解析覆盖大多数包，但有合法例外（多 LAUNCHER、动态注册、壳的代理 Activity、apktool 风格改过名的包）。

## Step 3 — 解析 smali 调用

### 支持的形态

```smali
invoke-static {p0}, Lcom/foo/Bar;->init(Landroid/app/Activity;)V
invoke-virtual {p0, v1}, Lcom/foo/Bar;->doIt(I)V
invoke-direct {p0}, Lcom/foo/Bar;-><init>()V
invoke-super {p0, p1}, Lcom/foo/Base;->onCreate(Landroid/os/Bundle;)V
invoke-interface {p1}, Ljava/lang/Runnable;->run()V
invoke-static/range {p0 .. p2}, Lcom/foo/Bar;->x(III)V
invoke-static {}, Lcom/foo/Bar;->noArg()V
```

`#` 注释与空行忽略。**一行出错不影响其它行**——用户粘一大段时，只应为那一行报错。

### 正则

```kotlin
HEADER     = ^(invoke-[a-z\-]+(?:/range)?)\s*\{([^}]*)\}\s*,\s*(.+)$
METHOD_REF = ^(L[^;]+;)\s*->\s*([^\s(]+)\s*\(([^)]*)\)\s*(\S+)$
```

### 寄存器列表

- 非 range：`{p0, v1}` → `["p0", "v1"]`，每项必须匹配 `^[pv]\d+$`
- range：`{p0 .. p2}` → 展开成 `["p0","p1","p2"]`，要求同族（都是 p 或都是 v）且 `to >= from`

### 参数类型解析

手写扫描器，支持 `L...;`、`[...`（数组）、`ZBSCIJFD`（基本类型）：

```
Landroid/app/Activity;ILjava/lang/String;  →  [Activity;, I, java/lang/String;]
[B                                          →  [[B 的数组形态]
```

## Step 4 — 定位 dex

```kotlin
for (name in ApkRepackager.listDexNames(apk)) {
    val bytes = readEntry(apk, name) ?: continue
    if (DexCallInjector.containsClass(bytes, ownerType)) { hitDex = name; break }
}
```

**必须逐 dex 找，不能全加载**：21 dex 的大包在手机上内存扛不住。`DexBackedDexFile` 是 lazy 的，只读类定义表不解析方法体，所以扫 30MB 包也是秒级。

dex 名排序：

```kotlin
sortedBy { name ->
    val n = name.removePrefix("classes").removeSuffix(".dex")
    if (n.isEmpty()) 1 else n.toIntOrNull() ?: Int.MAX_VALUE
}
```

`classes.dex` 排第一（`n` 为空视为 1），然后 `classes2.dex`、`classes3.dex`…

## Step 5 — 注入

### 5.1 定位目标方法

```kotlin
// ⚠️ 关键：dexlib2 的 methods 每次访问都新建对象
val classMethods = targetClass.methods.toList()
val existing = classMethods.firstOrNull {
    it.name == spec.methodName && signatureOf(it) == spec.methodSignature
}
```

`DexBackedClassDef.methods` 每次访问返回新对象，所以**必须先物化成 List**，后续定位与替换都基于同一批对象。用 `it === targetMethod` 做身份比较永远为 `false`，改写会静默失效。

### 5.2 寄存器换算

```kotlin
// p 区起点 = 总寄存器数 - 参数寄存器数
// 实例方法参数寄存器数 = 参数个数 + 1（含 this）
val paramRegCount = paramTypes.size + 1
val p0 = registerCount - paramRegCount
```

`p_i` → `registerCount - paramRegCount + i`
`v_i` → `i`（且必须 `< registerCount`）

### 5.3 指令形态选择

```kotlin
// 35c 最多 5 个寄存器，且编号 <= v15
val fits35c = phys.size <= 5 && phys.all { it <= 15 }
val contiguous = phys.isEmpty() || (phys.max() - phys.min() + 1 == phys.size)
```

| 情况 | 处理 |
|---|---|
| `fits35c` | `35c`（`invoke-*`） |
| 超 5 个 / 有 >v15，且连续 | `3rc`（`invoke-*/range`），自动降级 + 记 warning |
| 需要 range 但不连续 | **直接报错**，不产出非法 dex |

### 5.4 新建方法

方法不存在时：

```
registerCount = paramTypes.size + 1   // 恰好覆盖 p 区，不额外申请
accessFlags   = ACC_PUBLIC
方法体：
  [0] invoke-super/range {p0 .. pN}, <super>;-><sameName>(<sameSig>)   ← 若父类有
  [1..] 注入的调用
  [last] return-void（或 RETURN / RETURN_WIDE / RETURN_OBJECT，按返回类型兜底）
```

**父类调用判定**：

```kotlin
val superType = cls.superclass ?: return null
if (superType == "Landroid/app/Object;") return null
// 其余情况只要有同名同签名就补
```

不用方法名白名单的理由：白名单（只认 `onCreate`/`onResume`/…）会漏掉 `onNewIntent`、`onPostCreate` 这些同样需要 super 的生命周期方法，也会让用户在自定义方法上观察不到行为差异。

`Application.onCreate` 是空实现，理论上可以不调，但保持一致性更安全（父类可能是自定义 Application 并覆写了 onCreate）。

### 5.5 写出

```kotlin
val store = MemoryDataStore()
DexPool.writeTo(store, newDexFile)
```

`DexPool` 会重建整个 dex 的字符串/类型/方法池。**dex 版本头保持原样**，不做任何回填——这是与 apktool 路线最重要的差异。

## Step 6 — payload dex 校验

只做一件事：验魔数。

```kotlin
require(raw.size > 8 &&
    raw[0]=='d' && raw[1]=='e' && raw[2]=='x' && raw[3]=='\n'
) { "payload 不是合法 dex（缺少 dex\\n 魔数）" }
```

防止用户误选 zip / jar / 普通文件。不做更深校验（比如解析全量 dex）——那是注入方（用户）的责任，我们只保证「不是明显错的」。

## Step 7 — 重打包

`ApkRepackager.repack`，核心约束：

### 7.1 原样拷贝所有条目，只替换目标 dex

```kotlin
val e = ZipEntry(src.name).apply {
    time = src.time
    // ⚠️ 压缩方式跟随原条目：STORED 的别改成 DEFLATED
    method = if (src.method == ZipEntry.STORED) ZipEntry.STORED else ZipEntry.DEFLATED
    if (method == ZipEntry.STORED) {
        size = data.size.toLong()
        compressedSize = data.size.toLong()
        crc = CRC32().apply { update(data) }.value
    }
}
```

`resources.arsc` 与 `AndroidManifest.xml` 必须是 STORED 且 4 字节对齐，重压缩会破坏它们。

### 7.2 Manifest 绝不解码

`AndroidManifest.xml` 与其他条目一样按字节原样搬运。任何「解码成文本再写回」的路径都会产出系统不认的灰包（见 `踩坑记录.md` 坑 1）。

### 7.3 payload 追加为下一个空闲的 classesN

```kotlin
var n = 2
while (existingNames.contains("classes$n.dex")) n++
addedName = "classes$n.dex"
```

时间戳固定为 0，与 AGP 产物一致，保证可复现。

## Step 8 — 写入 Download

`OutputStore.saveApk`。

### Android 10+：MediaStore

```kotlin
val values = ContentValues().apply {
    put(MediaStore.Downloads.DISPLAY_NAME, name)
    put(MediaStore.Downloads.MIME_TYPE, "application/vnd.android.package-archive")
    put(MediaStore.Downloads.RELATIVE_PATH, "Download/ApkForge")
    put(MediaStore.Downloads.IS_PENDING, 1)
}
val uri = contentResolver.insert(MediaStore.Downloads.EXTERNAL_CONTENT_URI, values)
// 写入后
values.clear(); values.put(IS_PENDING, 0)
contentResolver.update(uri, values, null, null)
```

免权限。`IS_PENDING = 1 → 0` 是必须的两阶段提交，否则其他 App 可能在写入中途看到半个文件。

同时按 `RELATIVE_PATH + DISPLAY_NAME` 反推出 `File` 路径，因为**安装 APK 和「MT 定位」都需要真实路径**，MediaStore 只给 content URI。两个形态都保留在 `Saved(file, uri)`。

### Android 9 及以下

直接 `File` 写入，失败则退回 `getExternalFilesDir`，保证有产出。Manifest 里 `WRITE_EXTERNAL_STORAGE` 带 `maxSdkVersion="28"`。

### 同名处理

```kotlin
var candidate = name
var i = 1
while (File(dir, candidate).exists()) { candidate = "$base-$i.$ext"; i++ }
```

不覆盖用户已有产物。

## 配置的存取流程

### 保存

```
用户编辑（ConfigViewModel）
  │
  ├─ dex 源文件可能来自 cacheDir（MT 选的）→ 系统随时会清
  │
  ▼
ConfigStore.upsert(id, name, calls, method, sig, dexSource)
  │
  ├─ dexSource != null → 复制到 files/configs/<id>.dex
  ├─ dexSource == null 且已有 dex → **保留原 dex**（用户可能只改名字）
  └─ 写 files/configs/configs.json
```

**「保留原 dex」是必须的**：不加这个判断，用户改个配置名会把 dex 弄丢。

### 读取

```kotlin
list() → 解析 configs.json，按 updatedAt 降序
```

`Config.dexPath` 指向的文件可能已丢失（用户清数据、手动删）。UI 层用 `hasDex` 判断并提示「dex 文件已丢失，请重新选择」，不假设它一定在。

## 测试策略

核心逻辑不依赖 Android API，所以直接在 JVM 上跑真实 APK：

```bash
sh gradlew :app:testDebugUnitTest
# 可指定 APK：
sh gradlew :app:testDebugUnitTest -Dapkforge.testApk=/path/to/target.apk
```

`app/src/test/` 的断言清单见 `项目介绍.md`。

**为什么必须这样测**：二进制改写靠点 UI 验证是不负责任的——出错了只会看到「闪退」，不知道错在哪。当前 10 项测试里至少有 2 个真 bug 是靠它抓出来的（见 `踩坑记录.md` 坑 2、坑 5）。
