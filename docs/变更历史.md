# 变更历史

## v0.4 — 修三个真 bug，并把插件包做成「产物只多一个 dex」

v0.3 的反馈里有两条是**严重 bug**，不是审美问题：

1. **主页按钮飞到顶栏。** 贴底主操作栏是 `Box` 的直接子节点，却没写 `align`——
   `Box` 里不给 `align` 的子节点默认落在**左上角**，于是它在运行时叠到了顶栏上。
   而用户此前明确要求的是「删掉上面那个，用右下角代替」。
2. **插件包往宿主的 assets 写 json。** 用户的质疑「难道注入的时候把 json 也注入到
   assets 吗」正中要害：注入一个包应该只让它多一个 `classesN.dex`，
   改写宿主自有资产是越界，而且多一条可能断掉的通道（资产没写进去 = 注入成功但不弹窗）。

第三件事是能力缺口：本地弹窗载荷只做了「标题 + 正文 + 两个按钮」，
而它要对标的是清羽弹窗 7.0 的完整形态。

### 修掉的两个 bug

| 问题 | 根因 | 现在 |
|---|---|---|
| 主页按钮飞到顶栏 | `Box` 子节点漏 `align(BottomEnd)`，默认落左上角 | 全屏只有**一个**右下角悬浮按钮，常驻不隐藏 |
| 选了 APK 悬浮按钮才出现 | 条件写成了 `apkFile != null` | 「选 APK」本身就是它的第一个动作，永远可点 |
| 注入时往宿主 assets 写 json | 配置走「dex + 资产」两条通道 | **配置烘焙进 dex**，产物只多一个 `classesN.dex` |

### 插件包重做：复刻 7.0 的完整形态

上一版只有 2 个按钮、6 个字段。现在按 7.0 的字段名补齐（老配置能直接粘进来）：

```
总开关 / 智能弹出（24h）/ 静默天数 / 版本 / 强制性 / 点击外部关闭弹窗 /
弹窗风格（默认暗·默认亮·HOLO暗·HOLO亮·传统）/ 外部背景透明 /
标题 + 标题颜色 / 信息（多行）+ 信息颜色 /
同意·拒绝·中立 三个按钮 ×（开关 + 文本 + 颜色 + 动作 + 参数 + 提示）
```

动作白名单：`无 / 网址 / 退出 / 提示 / 智能 / QQ名片 / QQ群 / QQ咨询`，
其中 `网址` 只放行 `http`/`https`/`mqqapi`/`mqqwpa`（配置写什么就执行什么，
不加白名单等于把「跳任意 scheme」开放给写配置的人）。未知动作一律降级成「无」。

**关键实现：配置烘焙（`core/dex/PayloadBaker`）**

```
表单 ──► JSON ──► 替换 dex 里 PayloadConfig.baked() 的方法体 ──► 自包含的 dex
```

三个必须说清楚的点：

- 占位符必须由**方法返回**，不能写成 `static final String`。写成常量，javac 会把它
  内联到每个使用点，dex 里就有多份拷贝，烘焙时不知道该替换哪一份——
  替换了一处、别处仍是占位符，表现是「注入成功、不弹窗」，**没有报错**。
  `payload/dialog/build.sh` 在构建期数字节，不是 1 次就当场失败；单测再钉一遍。
- 烘焙后要**字节级**自检占位符已消失、配置真的在里面。用
  `String(dex, ISO_8859_1).contains(...)` 是错的：dex 的字符串池是 MUTF-8，
  中文按 Latin-1 解出来永远匹配不上，会把「烘焙成功」误判成失败。
- 代价写在界面上：改文案要重新导出 + 重新注入。这是刻意的取舍——
  本地弹窗是「一次性投放」，改文案的频率远低于「产物干净」的价值。

### 结构性移除（不是「约定别这么做」）

| 位置 | 移除了什么 | 为什么删而不是留 |
|---|---|---|
| `ApkRepackager.repack` | `extraEntries` 参数、`Stats.addedAssets` | 参数没了就写不出第二条通道，比注释「请不要用」可靠 |
| `ApkInjectPipeline.Input` | `extraAssets` | 同上 |
| `ConfigStore.Config` | `assets` 字段 | 配置只剩「调用行 + 模式 + dex」三样，语义变干净 |
| `PluginPack` | 配置 json 文件、`HOST_ASSET_PATH` | zip 从三件套变两件套（dex + call.txt） |

### 载荷自身的加固

- `Html.fromHtml(String,int)` 是 API 24 才有的，而载荷 min-api 是 21。
  `d8 --min-api` **不会**挡住「调用了设备上不存在的 API」，那是运行期
  `NoSuchMethodError`，正好砸在宿主启动那一瞬。改用单参数版本，
  并在 `build.sh` 里用 `platforms/android-21/android.jar` 再编一遍做硬门禁。
- `SharedPreferences` 换成独立文件 `apkforge_dialog`，不与宿主的默认偏好文件抢键名。
- 状态全改 `volatile` / 显式同步：载荷跑在宿主的多线程环境里。

### 测试

42 项（v0.3 的 36 + 新增 6）：

- `PluginPayloadTest`（4→11）占位符全 dex 唯一、烘焙往返逐字一致、
  三按钮槽位（含关掉的）都往返、7.0 老配置字段归一化、未知动作降级、
  阻断原因能说清下一步
- `InjectEndToEndTest`（+1）**产物只多一个 dex**：条目数 +1、原有条目一个不少、
  多出来的只能是 `classesN.dex`，且绝不能出现 `.json` 形态的条目
- 新增测试依赖 `org.json`（仅测试作用域）。Android 的 `android.jar` 在 JVM 单测里
  所有 `org.json` 方法都抛 "not mocked"，表单↔JSON 往返必须能离线验证。

## v0.3 — 细节打磨：从「能跑」到「能用」

v0.2 解决了信息层级（该点哪），但一上手就暴露一批**细节问题**：
日志是一条条列而不是实时一行、完成后进度条还赖在顶部、日志太长被省略号吃掉
且没法复制、深色模式下出现黑字、主按钮在屏幕上方够不着、任务卡只显示文件名
认不出是哪个包。这一版逐条修掉，并把「注入模式」和「批量」补上。

### 界面（逐条对应反馈）

| 问题 | 现在 |
|---|---|
| 日志应是一行实时状态，不是一列条目 | 运行中是**单行**：左侧呼吸点 + 阶段 + 当前动作 + 耗时，历史折叠在「展开」后 |
| 注入后界面切换像切片 | `AnimatedContent` 按 running / result / idle 三态做 240ms 交叉淡入，不再硬切 |
| 深色模式下还有黑字 | 主题固定深色 + `Surface` 兜住根节点 + 系统栏固定浅色图标（见 `踩坑记录` 坑 24） |
| UI 挤压 | 底栏固定、列表底部留 152dp、消息条与悬浮按钮互斥出现 |
| 「这次会注入什么」这个标题 | 改成「调用清单」——标题说的是内容，不是自问自答 |
| 调用行被省略号截断 | 默认 4 行，超出「展开全部」，单行**换行**不截断，右上角一键复制 |
| 配置里手选生命周期方法 | 去掉了。配置只管「注入什么」（调用行 + 载荷 + 模式）；注入点默认**自动** |
| 完成后 100% + 进度条还在顶部 | 完成后整块进度区撤掉，由结果卡接管这一屏 |
| 完成动画叠在内容上像遮挡 | 动画收进结果卡当卡头图标，与结论同一张卡 |
| 日志没有复制、过长省略 | 日志区可展开、可长按选择、可一键复制全文（带时间戳与阶段） |
| 页面重复 | 结果卡内聚为「结论 + 改了什么 + 产物 + 动作」一张；底栏动作收进卡内 |
| 主按钮在屏幕上方不方便点 | 改成贴底常驻主操作栏（⚠️ v0.4 推翻：那条栏漏了 `align`，运行时叠到顶栏，现改为唯一右下角悬浮按钮） |
| 右上角浪费 | 收进菜单：新建配置 / 批量注入 / 换一个 APK / 清空记录 |
| 任务卡只有文件名 | 图标 + 应用名 + 包名 + 文件名 + 版本，靠前三样认包 |
| 主卡两个标签是「配置 / 注入方法」 | 改成「配置 / 未签名」——签名迟早要占这个位置 |

### 新增能力

**注入模式（`InjectionMode` + `InjectionPlanner`）**

```
单次注入    启动切入点插一次
每次进入    onStart + onResume 各插一份，每次回到页面都执行
多点全覆盖  所有可插的生命周期点各插一份，用来看完整时序
替换方法体  丢弃目标方法原有指令，只留父类调用与注入（风险最高，UI 明示）
```

判定在纯 JVM 的 `InjectionPlanner` 里（`InjectionModeTest` 7 例钉住），
三条硬约束：只从同类清单取点、一律排除 native、`ONCE` 沿用 `resolve()` 的降级结论。

**批量注入**

选一个目录（`ACTION_OPEN_DOCUMENT_TREE`）→ 递归扫出 `.apk`（深 6 层、上限 50 个）
→ 挑一套配置 → 串行逐项注入。每项带自己的状态与失败原因；
批量的 VM 与控制台分开（不同生命周期的事不该共用状态）。

**插件包（`payload/` + `PluginPack`）**

本地弹窗载荷，源码在 `payload/dialog/src/`，构建脚本 `payload/dialog/build.sh`
用 `javac + d8` 直接产出 `PayloadDialog.dex`（9.3KB，无第三方依赖）。

载荷只依赖 `android.app.AlertDialog`/`org.json`，**没有网络代码**。

> ⚠️ 这一段描述的「配置从宿主 assets 读」已在 **v0.4** 被推翻：
> 配置改为烘焙进 dex，产物只多一个 `classesN.dex`。
> 保留原文只为让「为什么当时这么想」可追溯。

### 测试

36 项（原 23 + 新增 13）：

- `InjectionModeTest`（7）落点规划：不扩点、不重复、排除 native、跨体系不串清单
- `InjectEndToEndTest`（+2）替换方法体后指令只剩两条；额外资产进包且同名替换
- `PluginPayloadTest`（4）调用行与载荷 dex 的方法逐字一致、必须是 static/public、
  资产路径常量对齐、JSONC 去注释不吞字符串里的斜杠

## v0.2 — 控制台重构：把「该点哪」变成唯一答案

上一版的信息结构是「一屏把所有东西摊开」：配置、选包、类名、方法、结果、日志
都在注入页里抢位置。用户第一眼的问题是「我该点哪」——那就是设计失败。

这一版重做了信息架构，并补了三件真正影响可用性的东西：任务记录、
native onCreate 的自动降级、真实进度。

### 新的三层结构

```
侧边栏（平级四入口）
├── 控制台 ← 主场
│   ├── 锚点卡          选 APK ／ 开始注入，全 App 唯一主操作
│   ├── 任务记录        每条 = 包 + 配置 + 注入点 + 产物，可复用
│   ├── 注入配置（子页） 配置下拉 / 类名自动识别 / 方法推荐
│   └── 运行（子页）    进度条 + 快闪日志 + 完成动画 + 结果
├── 配置        完整增删改查
├── 签名        占位（说明卡在哪）
└── 关于
```

**为什么用页面而不是弹窗**：注入配置要放「配置下拉 + 类名 + 方法下拉 + 调用预览 +
载荷状态」五段，手机上做弹窗要么被键盘顶掉，要么内部套滚动。页面还有一个隐性好处：
返回键语义天然正确（选错了按返回就回控制台）。

### 新增能力

| 能力 | 为什么 |
|---|---|
| 任务记录（`TaskStore`） | 真正的痛点是「同一个包反复选、反复配」。记录里存 APK 私有副本 + 配置快照，换套配置再注入不用重新找文件 |
| APK 副本入库 | 用户选的包在 `cacheDir`，清缓存就没了。按「文件名 + 字节数」去重，注入十次只占一份 |
| `onCreate` native 时自动降级 | 加固壳 / `NativeActivity` 的 `onCreate` 没有字节码。按时机接近度退到 `onPostCreate` → `onStart` → `onResume` → `attachBaseContext`，并把原因写在界面上 |
| 注入点状态三态 | 「已有 / 将创建 / native 不可插」，用户一眼知道自己是覆写还是凭空造方法 |
| 真实进度 | 阶段带 weight，`progressOf()` 折算全局 0~1；重打包逐条目回调，日志飞滚是真事不是演的 |
| 悬浮锚点 | 记录多了往下滑，右下角浮出同一动作，不用往回找 |
| 侧边栏修好 | 平级切换与下钻分开，回退栈不再成环（`踩坑记录` 坑 20） |

### 删除

- `ui/anim/InjectSpinner.kt`、`InjectAnimation.kt`（v1 环形 / 风格切换器）：
  两版动画并存的成本是一个 `when`，但**风格选择器本身没有用户价值**——
  没人会因为能选动画而更想用这个工具。保留 v2 六边形（`InjectArtAnimation`），
  它出现在运行页进度数字左侧。
- `feature/inject/`、`ui/screen/inject/`：被控制台取代。

### 验证

23 项单元测试全过（原 10 项 + 新增 13 项），新增部分：

```
LifecyclePointsTest  11 例  native 降级顺序 / 不误改用户选择 / 全 native 时如实报错
                           替代点必须来自本类清单 / 换类后不沿用别体系的方法名
                           自定义方法名不被改 / 进度单调不减且收在 1.0
                           / 清单里每个签名都能被解析器认下
InjectEndToEndTest   6 例   新增「注入到生命周期替代点也补父类 super 调用」
                           → [INVOKE_SUPER_RANGE, INVOKE_STATIC, RETURN_VOID]
                           新增「重打包逐条目回调完整且不重复」
                           → 156 次回调 / 156 条目，index 1..156 连续
```

`ProgressHeader` / `LogTerminal` / `OutcomeGlyph` 的观感需要在真机上看，
本轮只保证编译通过、逻辑可验证，视觉待用户验收。

## v0.1 — 工程初始化与注入核心打通

**目标**：从零把「选 APK → 插调用 → 重打包」跑通。

### 构建配置

从 `sx_rjk` 移植，但不盲抄：

| 项 | 原值 | 改为 | 理由 |
|---|---|---|---|
| Gradle wrapper | 9.8.2 | **9.5.0** | 9.8.2 本地只有 0 字节 `.part`，9.5.0 已完整解压 |
| AGP | 9.4.1 | **9.3.0** | 本地缓存最高 9.3.0 |
| Kotlin | 2.4.21 | **2.4.10** | 同上 |
| JDK target | 17 | **21** | `compileOptions` + `jvmToolchain(21)`，配 `org.gradle.java.home` |
| `local.properties` | 无 | **新建** | 否则找不到 SDK |

抄来的：构建加速段（`configuration-cache` / `configureondemand` / `vfs.watch` / `kotlin.incremental`）、阿里云镜像仓库、jitpack。

没抄的：16KB 页对齐那一大段（ApkForge 无自有 native 库，是噪音）。

### 依赖决策

最终只引 **`smali-dexlib2:3.0.10`**（1.14MB）+ JUnit。

逐个排除了：

- `apksig` — 不重签名用不上；6 个类引用 `java.util.stream`，Android 无此包
- `apkzlib` — `bytestorage` 引用 `java.nio.file`，Android 已裁剪
- `org.smali:dexlib2:2.5.2` — 2020 停更，不认 dex 038/039
- `net.dongliu:apk-parser` — 拉 bcprov/bcpkix 1.58，只为读 Manifest 不值
- Room / KSP — 配置只有几条，注解处理器拖慢手机端构建

### 核心实现

- `AxmlManifest` — 手写二进制 AXML 解析（零依赖），取 LAUNCHER
- `DexCallInjector` — dexlib2 在方法头插 `invoke-static`，自动处理 35c/3rc 宽度
- `ApkRepackager` — `java.util.zip` 重打包，Manifest 逐字节原样搬运
- `SmaliCallParser` — 解析整行 smali invoke
- `ClassInspector` — 探测目标类已有方法 / 父类
- `OutputStore` — MediaStore 写 `Download/ApkForge/`
- `ConfigStore` — JSON 持久化「调用 + dex」

### 修复的 bug

| # | 现象 | 根因 |
|---|---|---|
| 1 | 注入静默失效，`onCreate` 首条仍是 `IGET_OBJECT` | `dexlib2` 的 `methods` 每次访问新建对象，`===` 恒 false |
| 2 | 新建方法不补 `super` | 方法体只有「注入 + return」 |
| 3 | 父类调用用白名单，探测方法名不在里面就跳过 | 硬编码枚举比数据驱动脆弱 |
| 4 | 配置混在主页面里无法使用 | 「管理」和「执行」放同一屏 |

### UI

- 侧边栏三页：注入 / 配置 / 关于
- 注入动画两版并存（v1 Canvas 环形、v2 SVG 六边形描边生长），用户可切
- 结果面板置顶，含完整路径 + 安装 / MT 定位 / 分享
- 日志折叠，单行终端风格

### 示例载荷

`tools/sample-payload/` — 真实 Java 源码 + 构建脚本，产物 `DemoDialog.dex`（2352 B）打进 `assets/sample/`。

Java 侧踩的坑：
- JDK 21 禁用 `-bootclasspath`，改 `--release 11 -classpath android.jar`
- `java -cp d8.jar` 找不到主类，要用 SDK 自带的 `d8` 脚本
- 弹窗必须 `postDelayed` 800ms，否则 `BadTokenException`
- 参数用 `Activity` 不用 `Context`

### 验证

10 项单元测试全部基于**真实 APK**：

```
E2E1: classes.dex / Landroidx/activity/ComponentActivity;  payload→classes10.dex
E2E2: 新建方法指令 = [INVOKE_SUPER_RANGE, INVOKE_STATIC, RETURN_VOID]
示例 dex 2352 B → inject(Landroid/app/Activity;)V 存在
```

## v0.2 — 目录重构与设计系统

### 目录分层

原来 `inject/` 一个目录里混着纯逻辑、Android IO、ViewModel 三种职责，`ui/` 平铺无分组。
按**依赖方向单向**重排：

```
ui → feature → data → core
```

| 层 | 内容 | 硬约束 |
|---|---|---|
| `core/` | AXML 解析、smali 解析、dex 注入、zip 重打包、流水线 | **禁止 `android.*`**，必须能在 JVM 上测 |
| `data/` | ConfigStore、OutputStore、FilePicker | 可依赖 Android IO，禁止反向依赖 |
| `feature/` | 两个 ViewModel | 禁止 Composable |
| `ui/design/` | 设计系统 + 组件库 | 禁止 import `core/feature`，保持零业务耦合 |
| `ui/screen/` | 三个页面 | 禁止手写色值/字号/弹簧字面量 |

`ui/theme/` 只保留 `Theme.kt`（Forge → MaterialTheme 映射），
删掉模板遗留的 `Color.kt` / `Type.kt`（无人引用）。

测试目录镜像主代码结构：`core/apk` `core/dex` `support`。

### 设计系统

新增 `ui/design/`，杜绝「每个组件单看还行、拼一起互不相干」：

- `ForgeTheme` — 深色单主题、青绿强调色、字阶 28/21/15/14/13/12/11/10
- `Motion` — 弹簧/缓动/时长/尺寸的**单一真相源**，禁止业务代码写 `spring(...)` 字面量
- `PressBounce` — 缩放按压反馈（移植自 jian_box `m3e/PressBounceModifier`）
- `ForgeComponents` — 顶栏、主/次/小按钮、徽标、状态、操作行、卡片、读数、折叠区
- `ForgeInputs` — 自绘单行/多行输入（避开 M3 TextField 的浮动标签虚胖）
- `ForgeSelectors` — 弹出面板、chip、chip 流式布局、选择行、文件行
