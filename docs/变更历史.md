# 变更历史

## v0.1 — 工程初始化与注入核心打通

**目标**：从零把「选 APK → 插调用 → 重打包」跑通。

### 构建配置

从 `sx_rjk` 移植，但不盲抄：

| 项 | 原值 | 改为 | 理由 |
|---|---|---|---|
| Gradle wrapper | 9.8.2 | **9.5.0** | 9.8.2 本地只有 0 字节 `.part`，9.5.0 已完整解压 |
| AGP | 9.4.1 | **9.3.0** | 本地缓存最高 9.3.0 |
| Kotlin | 2.4.21 | **2.4.10** | 同上 |
| JDK target | 17 | **21** | `compileOptions` + `jvmToolchain(21)`，配 `org.gradle.java.home` |
| `local.properties` | 无 | **新建** | 否则找不到 SDK |

抄来的：构建加速段（`configuration-cache` / `configureondemand` / `vfs.watch` / `kotlin.incremental`）、阿里云镜像仓库、jitpack。

没抄的：16KB 页对齐那一大段（ApkForge 无自有 native 库，是噪音）。

### 依赖决策

最终只引 **`smali-dexlib2:3.0.10`**（1.14MB）+ JUnit。

逐个排除了：

- `apksig` — 不重签名用不上；6 个类引用 `java.util.stream`，Android 无此包
- `apkzlib` — `bytestorage` 引用 `java.nio.file`，Android 已裁剪
- `org.smali:dexlib2:2.5.2` — 2020 停更，不认 dex 038/039
- `net.dongliu:apk-parser` — 拉 bcprov/bcpkix 1.58，只为读 Manifest 不值
- Room / KSP — 配置只有几条，注解处理器拖慢手机端构建

### 核心实现

- `AxmlManifest` — 手写二进制 AXML 解析（零依赖），取 LAUNCHER
- `DexCallInjector` — dexlib2 在方法头插 `invoke-static`，自动处理 35c/3rc 宽度
- `ApkRepackager` — `java.util.zip` 重打包，Manifest 逐字节原样搬运
- `SmaliCallParser` — 解析整行 smali invoke
- `ClassInspector` — 探测目标类已有方法 / 父类
- `OutputStore` — MediaStore 写 `Download/ApkForge/`
- `ConfigStore` — JSON 持久化「调用 + dex」

### 修复的 bug

| # | 现象 | 根因 |
|---|---|---|
| 1 | 注入静默失效，`onCreate` 首条仍是 `IGET_OBJECT` | `dexlib2` 的 `methods` 每次访问新建对象，`===` 恒 false |
| 2 | 新建方法不补 `super` | 方法体只有「注入 + return」 |
| 3 | 父类调用用白名单，探测方法名不在里面就跳过 | 硬编码枚举比数据驱动脆弱 |
| 4 | 配置混在主页面里无法使用 | 「管理」和「执行」放同一屏 |

### UI

- 侧边栏三页：注入 / 配置 / 关于
- 注入动画两版并存（v1 Canvas 环形、v2 SVG 六边形描边生长），用户可切
- 结果面板置顶，含完整路径 + 安装 / MT 定位 / 分享
- 日志折叠，单行终端风格

### 示例载荷

`tools/sample-payload/` — 真实 Java 源码 + 构建脚本，产物 `DemoDialog.dex`（2352 B）打进 `assets/sample/`。

Java 侧踩的坑：
- JDK 21 禁用 `-bootclasspath`，改 `--release 11 -classpath android.jar`
- `java -cp d8.jar` 找不到主类，要用 SDK 自带的 `d8` 脚本
- 弹窗必须 `postDelayed` 800ms，否则 `BadTokenException`
- 参数用 `Activity` 不用 `Context`

### 验证

10 项单元测试全部基于**真实 APK**：

```
E2E1: classes.dex / Landroidx/activity/ComponentActivity;  payload→classes10.dex
E2E2: 新建方法指令 = [INVOKE_SUPER_RANGE, INVOKE_STATIC, RETURN_VOID]
示例 dex 2352 B → inject(Landroid/app/Activity;)V 存在
```

覆盖：Manifest 逐字节不变、产物 dex 可解析、指令在头部、新建方法补 super、多行顺序保持、解析器 7 种形态、非法行必须报错、方法探测准确性、生命周期签名一致性。


## v0.2 — 目录重构与设计系统

### 目录分层

原来 `inject/` 一个目录里混着纯逻辑、Android IO、ViewModel 三种职责，`ui/` 平铺无分组。
按**依赖方向单向**重排：

```
ui → feature → data → core
```

| 层 | 内容 | 硬约束 |
|---|---|---|
| `core/` | AXML 解析、smali 解析、dex 注入、zip 重打包、流水线 | **禁止 `android.*`**，必须能在 JVM 上测 |
| `data/` | ConfigStore、OutputStore、FilePicker | 可依赖 Android IO，禁止反向依赖 |
| `feature/` | 两个 ViewModel | 禁止 Composable |
| `ui/design/` | 设计系统 + 组件库 | 禁止 import `core/feature`，保持零业务耦合 |
| `ui/screen/` | 三个页面 | 禁止手写色值/字号/弹簧字面量 |

`ui/theme/` 只保留 `Theme.kt`（Forge → MaterialTheme 映射），
删掉模板遗留的 `Color.kt` / `Type.kt`（无人引用）。

测试目录镜像主代码结构：`core/apk` `core/dex` `support`。

### 设计系统

新增 `ui/design/`，杜绝「每个组件单看还行、拼一起互不相干」：

- `ForgeTheme` — 深色单主题、青绿强调色、字阶 28/21/15/14/13/12/11/10
- `Motion` — 弹簧/缓动/时长/尺寸的**单一真相源**，禁止业务代码写 `spring(...)` 字面量
- `PressBounce` — 缩放按压反馈（移植自 jian_box `m3e/PressBounceModifier`）
- `ForgeComponents` — 顶栏、主/次/小按钮、徽标、状态、操作行、卡片、读数、折叠区
- `ForgeInputs` — 自绘单行/多行输入（避开 M3 TextField 的浮动标签虚胖）
- `ForgeSelectors` — 弹出面板、chip、chip 流式布局、选择行、文件行

### 关键修正
